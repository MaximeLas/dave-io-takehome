# The solid set, earned over six draws (2026-10-13)

**Pattern.** Not a change to the agent: a change to how the gate's rule 2 picks the questions it holds. Rule 2 holds every solid question to two passes of three, with no allowance, and a question entered the solid set by passing the three accept trials. Three passes are cheap to draw by luck: a question that passes 75% of the time does it 42% of the time (0.75³), then fails two trials of a later run and turns the gate red on code that did not change. On 13 Oct a pull request that changed only documentation, the agent identical to `main`'s, went red under rule 2 twice before merging, each time on a different solid question:

- [CI run 38314893054](https://github.com/MaximeLas/dave-io-takehome/actions/runs/38314893054), attempt 1: "Which instances would a deploy to the auto scaling group hit?" passed 1 of 3.
- [CI run 38319345402](https://github.com/MaximeLas/dave-io-takehome/actions/runs/38319345402), attempt 1: "Do any GitHub workflows deploy directly to a database?" passed 1 of 3; two trials listed the eight deploy workflows they had checked as the answer, on a question whose answer is none.

Each re-run went green, the second at 25, 25, 26.

**Hypothesis.** A second accept round on the questions that passed all three trials, up to three more runs each, stopped at the first failure, cuts lucky entries (0.75⁶, 18%, for a question at 75%) at a cost of at most three runs per entrant, and lowers the false-red rate of rule 2 on the same agent. Retaking the baseline under the new rule was expected to shrink the solid set by one or two questions.

**The change.** `npm run eval -- --accept` runs the second round after the three trials; the baseline file (format 2) records each entrant's second-round passes and the solid set explicitly, and rule 2 reads that list. The mean, the cost and both allowances still come from the three full trials; the round's cost is recorded, not gated. `npm run simulate-gate` draws the accept the same way, and `--rounds 1` keeps the old entry rule for a comparison on the same input.

**The accept.** One run on commit `b0fb213` (Haiku 5.5, effort high, prompt `1d555744`, the agent unchanged since the meaning-search merge), local, 13 Oct, eval id `2026-10-12T23-17-42-984Z-claude-haiku-5-5-high`, accepted in commit `8bf30c0`:

| | Trial 1 | Trial 2 | Trial 3 |
| --- | --- | --- | --- |
| Passed, against the key | 24 | 26 | 26 |
| Cost | 9.33c | 8.28c | 8.27c |

- **Allowances:** pass tolerance 2 (the spread), so rule 1 fails below a mean of 23.3; cost margin 1.06c (the spread), so rule 3 fails above 9.69c.
- **Second round:** 24 questions at 3 of 3 entered; all 24 passed three more runs, 72 runs in all, 18.2 cents.
- **Solid set:** 24 questions, against 25 in the baseline it replaces (commit `268529c`). The one that left, "Which instances can connect to rds-commerce-prod-4?", passed 2 of 3 in the trials (one trial added two instances); it left in the first round, not the second. None entered.

The second round removed no question on this draw, including the two that broke rule 2 in CI. The prediction of one or two fewer solid questions came true in count but not in cause. Six draws change the odds, not any single accept: a question at 90% still passes all six 53% of the time (0.9⁶), and one at 85% about four times in ten (0.85⁶ ≈ 0.38).

**The false-red rate, before and after.** `npm run simulate-gate` (100,000 simulated pairs of an accept and a later three-trial run of the same agent, seed 1), on the new baseline, each question's pass rate taken as its passes out of its draws in that file:

| Entry rule | Rule 1 | Rule 2 | Rule 3 | Any rule | Red twice |
| --- | --- | --- | --- | --- | --- |
| One round (`--rounds 1`) | 1.5% | 14.8% | 5.9% | 19.9%, one run in 5 | 7.5%, one in 13 |
| Two rounds (the gate) | 1.4% | 4.5% | 6.1% | 11.1%, one run in 9 | 3.7%, one in 27 |

Seed 2 gives the same figures within 0.2 points. Rule 2's share falls to under a third; its remaining red comes from the two questions at 2 of 3 in the baseline, which the model gives a 67% rate and which can still pass six draws. The total falls less, because rule 3 is now the largest single source: the new baseline's three costs (one trial at 9.33c, two at 8.28c) give a cost deviation of 0.61c, against which the 5% floor on the margin is narrow. That is a reading of three costs, and the next accept will move it.

The model behind these figures takes a question at 6 of 6 as never failing, so it misses the very failures that prompted the change: both questions that broke rule 2 in CI are at 6 of 6 here. Pooled over the thirteen local eval records of prompt `1d555744` (not committed; they span the agent before and after meaning search, 23 answered trials per question; the workflows question passed 21 of them and the deploy question all 23, so even pooled, the latter's CI red is out of the model's reach), the same command gives rule 2 at 12.5% with one round and 6.1% with two, any rule 18.6% and 13.9%, red twice 6.8% and 4.1%.

**Verdict.** Kept. The gate's false reds from rule 2 fall by about two thirds on the same input, for 18 cents per accept and nothing per pull request. Not fixed by this change, and named for the next ones: the padding on empty-answer questions behind the second CI red, which is the agent's to fix through the improvement loop, and the rule 3 noise, which the cost rule over the solid questions only (next steps, item 4) would narrow.

**Not measured.** Whether the second round's runs are independent of the trials' (they run minutes apart on the same model and prompt), which the simulation assumes.
